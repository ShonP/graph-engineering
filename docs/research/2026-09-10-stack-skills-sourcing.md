## Question

For each competency the Forge platform (`~/projects/forge-platform`) needs and the
graph-engineering plugin lacks, what is the best source to adopt, adapt, or

## Blocker (report only, not fixed)

`.claude/graph-profile.yaml` does not exist in `/Users/shonpazarker/projects/graph-engineering`
(checked: `find` returns nothing under `.claude/`). Per the plugin's own README,

## Answer, one paragraph

Of the ~20 competency rows evaluated, 7 have a credible **adopt**-grade source —
all official vendor repos with recent commits (FastAPI's own in-repo skill,
Pydantic AI's two skills from `pydantic/skills`, Grafana's `grafana/skills`,
Temporal's `skill-temporal-developer`, and Playwright's three in-repo skills) —
1 is **adapt** (Pydantic's own modeling skill actively recommends *against*
using Pydantic for internal classes, which conflicts with the owner's house
rule of "Pydantic models everywhere, no dataclasses"; adopt the mechanics,
override the recommendation), and 11 are **write from vendor docs** because no
vendor or well-maintained community skill exists for that surface at all: `uv`,
Microsoft Agent Framework, Helm, Argo CD, kubectl/Kubernetes, CloudNativePG,
Envoy Gateway, Envoy AI Gateway (which has quietly renamed/moved to
`theagentrouter/agent-router`), Bruno's `bru` CLI, SOPS/age, and kustomize.
Every GitHub, Helm, Argo, CloudNativePG, Envoy, Bruno, and SOPS org search
turned up only internal contributor skills (how to review a PR against *their*
codebase) or single-digit-star personal repos — nothing that teaches an agent
to *use* the tool in someone else's repo, which is what Forge needs.

## Recommendation

### Proposed skill group directories under `skills/`

```
skills/
  python/            # uv (write), pydantic-v2 (adapt), fastapi (adopt), pydantic-ai (adopt)
  agents/             # microsoft-agent-framework (write)
  k8s-gitops/        # helm, argocd, kubectl, kustomize, cloudnativepg,
                       # envoy-gateway, envoy-ai-gateway, sops-age (all write)
  temporal/          # temporal-developer (adopt, vendored)
  qa/                # playwright-cli, playwright-trace, playwright-component-testing
                       # (adopt, vendored), bruno (write)
  observability/     # grafana-logql-promql-traceql (adopt, vendored)
```

This mirrors the existing convention (`skills/android`, `skills/ios`,
`skills/react`) — one directory per stack, each with its own `SKILL.md` subdirs
and, where it becomes a plugin dependency, no local copy at all.

### `plugin.json` dependencies vs vendored

**Become `plugin.json` `dependencies` entries** (already ship their own
`.claude-plugin/plugin.json`, so they are true installable plugins, not just
skill trees):
- `pydantic` (from `pydantic/skills`, plugin `plugins/pydantic`) — pin `~1.x` once the maintainers cut a tag; today there is no version tag visible from the repo listing, so this needs a follow-up check before it can be a real semver constraint per spec §4.2 rule 4 ("never a bare name").
- `building-pydantic-ai-agents` (plugin `plugins/ai`)
- `pydantic-ai-harness` (plugin `plugins/pydantic-ai-harness`)

Open question for the owner: confirm these are actually published to a
Claude Code plugin marketplace (`/plugin marketplace add pydantic/...`) — this
research only confirmed the `plugin.json` files exist in-repo, not that they
are marketplace-listed the way `graph-engineering` itself is.

**Vendored, pinned by commit SHA, with the vendor's license file copied
alongside** (bare `SKILL.md` trees, no `plugin.json`, per spec §4.1):
- `temporalio/skill-temporal-developer` (whole repo, MIT) → `skills/temporal/`
- `grafana/skills` subset (`grafana-core/promql`, `grafana-lgtm/loki`,
  `grafana-lgtm/tempo`) (Apache-2.0) → `skills/observability/`
- `microsoft/playwright` subset (3 dirs under
  `packages/playwright-core/src/tools/skills/`) (Apache-2.0) → `skills/qa/`
- `fastapi/fastapi` single file (`fastapi/.agents/skills/fastapi/SKILL.md`)
  (MIT) → `skills/python/fastapi/`

**Write from vendor docs** (new `SKILL.md` authored in this repo, cite the doc
URLs in the table above as the source-of-truth comment at the top of each
file): `uv`, Microsoft Agent Framework, Helm, Argo CD, kubectl/Kubernetes,
CloudNativePG, Envoy Gateway, Envoy AI Gateway, Bruno, SOPS/age, kustomize.
