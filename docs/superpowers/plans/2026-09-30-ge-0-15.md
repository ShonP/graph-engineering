# graph-engineering 0.15 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to run this plan wave by wave. Dispatch only the `graph-engineering` roster: `implementer` for `standard` tasks, `implementer-simple` for `small` tasks, and `reviewer` on opus. Never use `general-purpose`. Tasks inside one wave run in parallel, each in its own worktree, and their writable paths do not overlap. Waves run in order. Each task's full brief lives in the dispatch (the `tasks[]` entry). This document holds the contracts those briefs share.

**Goal:** Ship graph-engineering 0.15, meaning all four roadmap waves: stop the bleeding, front door and lanes, parallelism, and the full loop. The plugin stays generic, for any repo the owner builds (TS, Python, Swift, Kotlin, Go, infra). Opus replaces fable, and every wave is measured.

**Architecture:**
- Deterministic helpers stay in `scripts/graph_control/`, and that module never executes project commands.
- The module gains a plug-in command registry (`scripts/graph_control/commands/`), so each new subcommand is a new file and `cli.py` stops being a shared hotspot.
- Anything that executes a project or consumer command lives outside the module: beside the hooks in `hooks/scripts/`, or as a standalone script in `scripts/*.sh|*.py`.
- Consumer specifics live only in the consumer's own files: `.claude/graph-profile.yaml`, `.claude/graph-checks.json`, local agents and rule packs.

**Tech stack:**
- Hooks: bash plus the Python ≥ 3.11 stdlib.
- graph_control: `uv run --script` with PEP 723-pinned PyYAML 6.0.2, plus wcmatch from wave 2.
- Agents, commands, graphs and skills: Markdown prompts.
- CI: GitHub Actions calling one test runner.

**Spec:** `docs/research/2026-09-30-next-version-roadmap.md` (read it in full). Two things override it where they disagree: the wave-0 spike verdicts (2026-09-30, Claude Code 2.1.285, summarised below) and the owner decisions below.

**Profile:** this repo has no `.claude/graph-profile.yaml`. The stacks and routing below are defined by this plan (OQ1).

## Owner decisions (binding, 2026-09-30)

1. **The plugin is generic.**
   - Plugin core carries no Koach, fitness or forge paths, stacks or conventions.
   - Consumer specifics go in the consumer's profile, checks file, local agents and rules.

   - opus: implementer, reviewer, reviewer-lead, planner, ux-designer.
   - sonnet: implementer-simple, researcher, researcher-spike, qa, qa-lead, retro.
   - Never haiku, fable or `general-purpose`.
   - The profile's `policy:` block is the single source of these tiers.
3. **Build the whole roadmap.** Priorities: token efficiency, low overhead, speed, delegating only when needed, and more parallelism, including nested leads where the spikes proved them.
4. **Auto-merge on full green for low-risk classes: yes.**
   - The template default stays `merge: owner` with `auto_classes: []`.
   - Consumers opt in through `gates.auto_classes`.
5. **QA harness.**
   - The plugin ships only the generic contract and a template.
   - Login and throwaway-user helpers live in consumers, behind `runtime.command`.
   - Drivers stay in the run directory.

## Review focus

The five failure modes most likely to bite, each with its owning test:

1. **A repo loses Stop and lint checks silently after upgrading.** Autodetect is removed and the hooks become opt-in.
   - Doctor raises a `warn` when the profile exists but `.claude/graph-checks.json` does not (w2-doctor, AC-W2-DR-01).
   - graph-init proposes the file (w2-profile-init).
   - CHANGELOG marks the change as breaking (integrator).
2. **The Stop hook loops.** An asyncRewake exit 2 re-fires on every Stop.
   - `stop_hook_active=true` means exit 0 without running anything (w1-hooks-checks, AC-W1-STOP-02).
3. **The guard rewrite drops Agent input fields.** `updatedInput` replaces the whole `tool_input`.
   - Tests assert that every original key survives (w1-guard-agent, AC-W1-GA-02).
4. **The destructive guard nags on everyday commands.** Examples: `rm -rf node_modules`, `docker compose -p ge-x down -v`, a quoted `rm -rf /` inside an echo or a commit message.
   - These are negative cases (w1-guard-destructive, AC-W1-GD-02).
5. **The memo replays a stale verdict.** This can happen after an untracked file or a config change.
   - The key includes untracked content and the config hash (w2-check-memo, AC-W2-MM-02).

## Shared contracts

These are the interfaces sibling tasks build against. Each brief repeats the part it needs.

**C1 `.claude/graph-checks.json` v1 (extended, backward compatible)**
- Shape: `{version: 1, test?: {argv, timeout_seconds 1-600 (600)}, precheck?: {argv, timeout_seconds 1-60 (10)}, lint?: {argv with exactly one element "{file}", extensions [".x",...], timeout_seconds 1-120 (60)}}`.
- Unknown keys are rejected.
- `{file}` is replaced with the path relative to the candidate root, as one argv element.
- The loader is `hooks/scripts/checks_config.py`.
- The example is `templates/graph-checks.json`.
- Without the file, the Stop and lint hooks do nothing. This is a breaking change from 0.14's autodetect.

**C2 hooks.json registrations**

| Event | Matcher | Handler | Settings |
| --- | --- | --- | --- |
| PostToolUse | `Edit\|Write` | `lint-touched-file.sh` | `async: true`, timeout 130 |
| PreToolUse | `Bash` | `guard-destructive.sh` × 4 | one `if` each: `Bash(git push*)`, `Bash(git remote*)`, `Bash(rm *)`, `Bash(docker *)`; timeout 10 |
| PreToolUse | `Agent\|Task` | `guard-agent.sh` | timeout 15 |
| Stop | (none) | `test-before-stop.sh` | `asyncRewake: true`, timeout 620, no `if` |
| SessionStart | `startup\|clear\|compact` | `print-handoff.sh` | wave 1 |
| SessionStart | `startup` | `doctor-on-start.sh` | added in wave 2, timeout 5 |

**C3 graph_control command modules**
- The package is `scripts/graph_control/commands/`. `__init__.py` exports `Output(text, exit_code=0)` and `iter_commands()`.
- Each module defines `NAME`, `HELP`, `add_arguments(parser)` and `run(args) -> dict | Output`, and imports heavy dependencies inside `run`.
- The CLI wraps a dict as `{status: PASS, ...}` and prints an `Output` verbatim.
- Errors produce the existing BLOCKED JSON and exit 1.
- A NAME that collides with an existing subcommand raises at discovery.

**C4 profile `policy:` block**
- Shape: `{roles: {agent type: opus|sonnet}, never: [haiku, fable], block_types: [general-purpose]}`.
- Wave 1 roles: planner, ux-designer, implementer and reviewer are opus; implementer-simple, researcher, qa and retro are sonnet. Wave 3 adds reviewer-lead (opus), qa-lead (sonnet) and researcher-spike (sonnet).
- Guard semantics:
  - A type in `block_types` is denied.
  - A requested model in `never` is denied.
  - A known role with an absent or different model is allowed, with `updatedInput` = the full original input + `model: <tier>`.
  - A `policy-override: <reason>` line skips enforcement and appends a line to `.graph/ledger.md`.
  - No profile, no policy, or invalid YAML means a no-op (fail-open, documented).

**C5 agent frontmatter**
- Allowed keys: name, description, model, effort, maxTurns, tools, disallowedTools, skills, memory, background, omitClaudeMd, color.
- Rejected keys:
  - permissionMode, hooks, mcpServers and initialPrompt, because plugins ignore them.
  - isolation, because of spike d.
- `model` must be opus or sonnet.
- `tools` must be an explicit list.
- Every `skills` entry is qualified and resolves to exactly one skill.
- Every graph `agent:` value is `engine` or an existing agent.
- `maxTurns`: implementer 200, implementer-simple 60, qa 250, retro 40, qa-lead 150, reviewer-lead 120, researcher-spike 25.

**C6 findings.json v1**, written by review and by qa
- Shape: `{schema_version: 1, verdict, reviewed: {base, head}, findings: [{id, severity blocking|important|nit, file, line, scenario, rule, confidence, route patch|bad_plan|intent_gap|defer, needs_author_context, status open|fixed|refuted}]}`.
- `graph-control findings <files...> --counts` reports only open findings.
- An absent file is BLOCKED, never zero.

**C7 risk and depth**
- Profile `risk:` rows are `{id, paths: [globs], keywords: [strings]}`. Paths are matched with wcmatch; keywords are matched case-insensitively against added diff lines.
- `graph-control depth --root --base --profile` returns `{depth: lint|single|panel, changed_lines, files, risk_rows, reasons, untracked_excluded}`.
- Gate classes: `gates.owner_classes` and `gates.auto_classes` name risk ids, plus `none` for a diff that matches no risk row.

**C8 check memo**
- The file is `<git common dir>/graph-engineering/checks-state.json`.
- The key is sha256 of `{root, revision, dirty_sha256, argv, config_sha256}`.
- The verdict is pass, fail or timeout.
- `GRAPH_CHECKS_NO_MEMO=1` bypasses it.
- `graph-control check <root> --reuse` reads it and never executes anything.

**C9 decision cards**, in `.graph/<run>/decisions.md`
- One line each: `- [ ] D<n> <what> | why owner | default | cost of waiting | reversible: yes|no | meanwhile | redo if other`.
- A reversible card has its default applied, and is marked `[x] ... (default applied)`.

  - `schema_version: 2`

  - `gates.owner_classes`, `gates.auto_classes`

**C11 run grouping**
- Every Agent `description` starts with `<first 8 chars of run id>:<node>`.
- Status and session_usage group by it.

**C12 helper CLIs**
- `graph-control waves <plan.json> [--max-width 4]`
- `graph-control host-check --root [--min-free-gb 20] [--profile]`
- `scripts/lane-run.sh <lane> [--slots N] [--wait-seconds S] -- argv` (exit 75 when busy)
- `scripts/worktree-gc.sh [--apply] [--base ref]`
- `hooks/scripts/wait-run.sh --log <abs> [--max-block 270, capped at 590] [-- argv]` (exit 75 when partial)

**C13 plan.json schema v2 and briefs**
- `schema_version` 1 or 2. Version 2 allows `success_signals: [{goal, source prometheus|sentry|sql-readonly|command, command argv, success_condition, window_days 1-90}]`. An empty list requires `success_signals_reason`.
- `graph-control validate-briefs <run-dir>` checks that every task has a `tasks/<id>.md` of at most 300 lines, with at most 35% fenced lines.

**C14 measure**
- `python3 scripts/measure_signals.py <run-dir> [--now]` runs a signal's argv once its window has elapsed.
- The command must output a scalar. Anything else is rejected as `no data (rejected: non-aggregate output)`.
- It writes `measure.md` and appends a line to the ledger.

**C15 digest and render**
- `graph-control digest --root --base [--plan] [--profile]` is read-only, uses git only, and prints at most 60 lines.
- `graph-control render [--write|--check]` generates `docs/playbooks.md` (Mermaid) from `graphs/*.md`.
